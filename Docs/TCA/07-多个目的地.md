# 多个目的地

对照源码：`TCA/Contacts/ContactsFeature.swift`、`TCA/Contacts/ContactsView.swift`

教程原文：[Multiple presentation destinations](https://pointfreeco.github.io/swift-composable-architecture/1.10.0/tutorials/composablearchitecture/02-02-multipledestinations)

联系人列表能弹出两种界面：添加联系人的 sheet，以及删除前的确认 alert。两种界面互斥，同一时刻只能出现一个。

## 每个目的地一个可选值会怎样

如果写成两个字段：

```swift
@Presents var addContact: AddContactFeature.State?
@Presents var alert: AlertState<Action.Alert>?
```

每个字段都有「有值 / 无值」两种情况。n 个可选字段一共有 `2^n` 种组合，其中合法的只有「全部关闭」和「恰好打开一个」。

| 可选字段数量 | 全部分组合 | 非法组合（同时打开两个或更多） |
|---|---|---|
| 2 | 4 | 1 |
| 3 | 8 | 4 |
| 4 | 16 | 11 |

非法组合会漏进应用：你无法单凭类型知道现在到底弹出的是谁。

## 收成一个枚举

```swift
@Reducer
enum Destination {
    case addContact(AddContactFeature)
    case alert(AlertState<ContactsFeature.Action.Alert>)
}
```

父状态只留一个可选值：

```swift
@Presents var destination: Destination.State?
```

`nil` 表示都没弹出。非 `nil` 时一定是其中某一个 case。以后再加一种弹出界面，就加一个 case。

`@Reducer` 加在枚举上时，case 里写的是 reducer 类型，不是 State。宏会生成：

- `Destination.State`：每个 case 带上对应的状态
- `Destination.Action`：每个 case 带上对应的动作
- 按 case 转发的 reducer

`AlertState` 会被认成临时状态。它没有自己的子 reducer，按钮动作直接回到父功能；处理完后 `ifLet` 把 `destination` 置为 `nil`。确认框上的 Cancel 不用建模，系统关闭走 `.dismiss`。

## 父功能怎样打开和接收

打开 sheet：

```swift
state.destination = .addContact(
    AddContactFeature.State(
        contact: Contact(id: UUID(), name: "")
    )
)
```

打开 alert：

```swift
state.destination = .alert(
    AlertState {
        TextState("Are you sure?")
    } actions: {
        ButtonState(role: .destructive, action: .confirmDeletion(id: id)) {
            TextState("Delete")
        }
    }
)
```

`AlertState` 是值。标题、按钮、按钮被点之后要发的动作，都写在状态里。测试可以检查 `state.destination`，不用真的把 alert 弹出来。

接收子功能的保存，以及 alert 的确认，都从 `.destinationAction(.presented(...))` 拆进去。其余展示动作落在 `case .destinationAction`，返回 `.none`。

## 视图钻进某一个 case

```swift
$store.scope(\.destination?.addContact, action: \.destinationAction.addContact)
$store.scope(\.destination?.alert, action: \.destinationAction.alert)
```

`@Reducer` 给枚举加了 `@CasePathable`，所以 key path 可以写成 `\.destination?.addContact`，只在当前 case 匹配时有值。

## 和 1.10 教程的两处写法差别

工程依赖的是 TCA 1.26，行为与教程相同的两处写法已经换成现在的形式。

教程写 `@Reducer(state: .equatable)`，让宏给 `Destination.State` 加上 `Equatable`。这个参数后来废弃了，工程里改成：

```swift
extension ContactsFeature.Destination.State: Equatable {}
```

教程的视图写 `$store.scope(state: \.destination?.addContact, action:)`。第一个参数的标签后来去掉了，现在写成 `$store.scope(\.destination?.addContact, action:)`。
