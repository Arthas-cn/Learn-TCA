# 一个功能的三件套

对照源码：`TCA/Counter/CounterFeature.swift`、`TCA/Counter/CounterView.swift`、`TCA/App/TCAApp.swift`

一个功能是整个类型，比如 `CounterFeature`。它里面有三样东西。

- **State**：界面现在的数据。计数器的数字、有没有在加载、定时器开着没有，都在这里。
- **Action**：刚刚发生的事。用户点了按钮，或者一次异步工作结束了。
- **`Reduce`**：收到一个 Action 后，怎样修改 State，以及要不要开始后续工作。代码就是 `Reduce { state, action in ... }`。

后面的笔记里，「功能」只指整个类型，「`Reduce`」只指这个闭包。

## 这些词各指一样东西

库的拼写很容易和上面的 `Reduce` 混在一起：

| 写法 | 指什么 | 在计数器里 |
|---|---|---|
| 功能 | 整个类型 | `CounterFeature` |
| `@Reducer` | 标在类型上的宏 | 标在 `struct CounterFeature` 上面 |
| `Reducer` | 协议。宏让功能类型遵守它 | `CounterFeature` 因此可以写成 `CounterFeature()` 交给 Store |
| `body` | 协议要求功能交出来的实现 | `var body: some ReducerOf<Self>` |
| `Reduce` | `body` 里手写的闭包 | `Reduce { state, action in switch action { ... } }` |

`ReducerOf<Self>` 是 `body` 的类型。`Self` 就是当前这个功能，所以这段实现处理的是 `CounterFeature.State` 和 `CounterFeature.Action`。

`CounterFeature` 的 `body` 里只有一个 `Reduce`。`AppFeature` 的 `body` 里还有 `Scope`，最下面才是它自己的 `Reduce`。连接器负责把动作转给子功能，改状态的语句仍然写在某个 `Reduce` 里。

## 单向数据流

视图读 State，把用户操作变成 Action 交出去。`Reduce` 修改 State。State 变了，SwiftUI 重绘。

```text
视图读 store.count
    │
    │  store.send(.incrementButtonTapped)
    ▼
Reduce 执行 state.count += 1
    │
    ▼
视图再次读取，数字变了
```

视图里不写 `count += 1`。计数器视图只做这件事：

```swift
Button("+") {
    store.send(.incrementButtonTapped)
}
```

对应的 `Reduce` 分支：

```swift
case .incrementButtonTapped:
    state.count += 1
    state.fact = nil
    return .none
```

`.none` 表示这次没有后续工作，状态已经改完。

## Store

`Store` 是运行时容器。它保存当前 State，把 `send` 进来的 Action 交给功能的 `body`，最后进入 `Reduce`。

一棵功能树只在根上创建一次 Store：

```swift
ContactsView(
    store: Store(initialState: ContactsFeature.State()) {
        ContactsFeature()
            ._printChanges()
    }
)
```

`_printChanges()` 会在每次状态变化时把前后差异打印到控制台，学习时可以一直开着，看 Action 进来之后 State 哪几个字段变了。

子界面拿到的也是 Store，但是从根 Store 上切出来的一块。切法写在 [组合](03-组合.md) 和后面的各篇里。

## State 为什么要 Equatable

`CounterFeature.State`、`Contact`、`ContactsFeature.State` 都遵守 `Equatable`。

测试靠比较「动作之前的状态」和「动作之后的状态」来判断 `Reduce` 有没有改对。SwiftUI 也靠相等来跳过没有变化的刷新。放进 State 的模型，默认就让它可比较。

## 一个功能里的状态都放在一起

计数器同时有数字、网络结果、加载标记、定时器开关。它们是同一个功能的状态，所以放在同一个 `State` 里，由同一个 `switch` 修改。

不要在视图里另存一份 `count`。视图显示的值来自 `store.count`，唯一能改它的地方是 `Reduce`。
