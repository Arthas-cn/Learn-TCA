# 组合

对照源码：`TCA/AppFeature.swift`、`TCA/ContactsFeature.swift`、`TCA/AddContactFeature.swift`

组合就是把多个小功能嵌成一棵树。整棵树只有一个 Store。子功能不认识父功能。父功能拥有子功能的状态，并用连接器把子 reducer 接进来。

## 为什么要拆

添加联系人的表单只关心草稿姓名、保存和取消。它如果直接去改联系人列表，就只能用在这一个界面里。

列表关心「什么时候弹出表单」和「保存之后把人放进数组」。它不关心文本框里每一个字怎样写回草稿。

两边各自保持一份 State、一组 Action、一个 Reducer。组合只解决它们怎么嵌在一起。

## 父状态里放子状态，父动作里包子动作

`AppFeature` 的两个页签一直都在：

```swift
struct State: Equatable {
    var tab1 = CounterFeature.State()
    var tab2 = CounterFeature.State()
}

enum Action {
    case tab1(CounterFeature.Action)
    case tab2(CounterFeature.Action)
}
```

计数器自己的动作是 `.incrementButtonTapped`。到了父功能这一层，它变成 `.tab1(.incrementButtonTapped)`。`Scope` 看到这层包装，就把 `state.tab1` 交给 `CounterFeature` 的 reducer。

联系人的表单多数时候不存在，所以子状态是可选的，动作外面还多一层「当前是不是展示中」：

```text
.destination(.presented(.addContact(.setName("Blob"))))
```

## 三种接法

按子功能的生命周期选择。

| 子功能什么时候在 | 父状态 | 连接器 | 工程里的例子 |
|---|---|---|---|
| 一直都在 | 普通字段 | `Scope` | 两个计数器页签 |
| 没有，或者恰好一个 | 可选值 | `ifLet` | 添加联系人、删除确认框 |
| 零个到很多个 | 带 id 的数组 | `forEach` | 本工程还没有。导航栈是这种 |

`forEach` 和前两种是同一件事：父动作里包着子动作和 id，连接器在数组里找到那一份子状态，交给对应的子 reducer。

## 父功能自己的 Reduce

`Scope` 或 `ifLet` 下面还有一个 `Reduce { state, action in ... }`。这是父功能自己的逻辑，用来处理「子功能之间要协作」的动作。

两个计数器互不影响，所以 `AppFeature` 里的这个 `Reduce` 是空的，直接返回 `.none`。

联系人列表要在收到「请保存」之后修改 `contacts`，这段逻辑就写在 `ContactsFeature` 自己的 `Reduce` 里。子功能只负责把联系人交出来。

## 视图跟着同一棵树切

根视图持有整棵树的 Store。子视图要的是子功能那一块 Store，用 `scope` 从父 Store 上切下来。

`AddContactView` 的类型是 `StoreOf<AddContactFeature>`。它读不到 `contacts`，也发不出 `deleteButtonTapped`。
